# Cold Shower Prompt Patterns

Use these patterns as scaffolds. Adapt them to the user's context; do not paste them mechanically.

## Before Coding

```text
我怀疑我没说清楚。你先别写代码。
请像苏格拉底一样追问我，直到需求、边界、用户、验收标准和失败场景足够清楚。
每轮最多问 5 个问题；不要给情绪价值。
```

## Requirement Pressure Test

```text
请先泼冷水：这个需求里最可能没想清楚的 5 个点是什么？
哪些是用户真的需要，哪些只是我自以为需要？
请给出最小可验证版本、验收标准、非目标，以及 3 个必须处理的边界场景。
最后给出 Proceed / Clarify / Test / Kill 判定。
```

## Technical Plan Review

```text
请对这个技术方案做一次极不友好的 review。
指出 3 个未验证的隐含假设、3 个过度工程点、3 个未来最可能后悔的技术债。
按严重程度排序，并给出更小、更稳、更容易回滚的替代方案。
```

## Code Review

```text
请进行一次没有情绪价值的 code review。
优先找真实 bug、回归风险、数据一致性问题、安全问题、并发/状态问题、测试缺口。
不要泛泛而谈；每个问题都要说明触发条件、影响和修复方向。
```

## Product Or Pricing Decision

```text
请扮演一个刚听完我竞争对手路演、已经对我有偏见的投资人。
说出你最不想投我的 3 个理由。
再指出我自以为是的优势里，最经不起推敲的那一个。
最后给出我必须拿出什么证据才能反驳你。
```

## Zou Ji Anti-Flattery Audit

```text
请用“邹忌审美偏差”审视你接下来本能想给我的回答：
你哪里可能因为“私我、畏我、有求于我”而过度顺从？
你最不愿意直接说破的问题是什么？
如果你不需要讨好我，你会把哪个结论说得更狠？
最后把回答改成不讨好、不安慰、但可验证的版本。
```

## AI-Native Startup Stage Gate

```text
请把我的项目放进 Idea / MVP / Launch / Scale 四阶段里判断。
不要鼓励我动手，先判断我卡在哪个阶段。
每个阶段分别指出：目标、最大陷阱、应该用 AI 反驳我的地方、进入下一阶段的证据。
最后只给一个闸门判定：Proceed / Clarify / Test / Kill。
```

## Context Drift Technical Debt

```text
请专门检查这个 AI 辅助生成的代码库是否出现“上下文漂移”：
规格是否缺失？架构是否前后不一致？命名和边界是否漂移？
哪些地方说明代码库已经失去连贯心智模型？
请按会导致未来维护失败的严重程度排序。
```

## Market Entry

```text
请先不要鼓励我进入这个市场。
列出这个赛道里过去 5 年失败或明显退场的产品，按死法分类。
它们当年也像我一样自信。请指出我现在哪一点和它们当年最像。
如果需要当前事实，请先查证来源。
```

## Pitch Or BP

```text
请扮演一个疲惫、挑剔、刚看过 20 个类似项目的投资人。
指出我这个 pitch 里最像自我感动的部分、最弱的一页、最怕被追问的数字。
不要改得更漂亮，先判断哪里站不住。
```

## Personal Decision

```text
请扮演 5 年后已经因为这个决定后悔了的我，给现在的我写一封信。
具体写出我失去了什么、低估了什么、现在最致命的自欺是什么。
不许安慰，不许鸡汤；最后给出 3 个我现在就该验证的问题。
```

## Six Hats Cold Shower

```text
请用六顶思考帽会诊这个决定，但黑帽必须最严格。
白帽：事实和缺失证据。
红帽：我可能被什么情绪绑架。
黑帽：最可能失败的路径。
黄帽：真正成立的收益，不许空泛。
绿帽：更小、更便宜、更可逆的替代方案。
蓝帽：下一步决策流程、验证指标、停止条件。
```

## Launch Gate

```text
在你开始执行前，先给我一个冷水闸门：
如果这件事不该做，最强的 no-go 理由是什么？
如果可以做，必须满足哪 3 个条件？
如果条件不满足，最小的验证实验是什么？
最后只给一个判定：Proceed / Clarify / Test / Kill。
```
